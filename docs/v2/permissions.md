# บทบาทและสิทธิ์ (V3 Secure Faculty Workspace, #214)

> **V3 ต่างจาก V2** ตั้งแต่ #291: `staff` ใน V3 ไม่มีสิทธิ์สร้าง/แก้ master data (อาจารย์, สาขา, เกณฑ์, รอบ, ตำแหน่ง) อีกแล้ว เหลือแค่ดู report (จำกัดสาขาตัวเอง) และรับเรื่องใบภาระงาน (`receiver`) เท่านั้น ทุกอย่างที่เคยเป็น `staff` เปลี่ยนเป็น `admin` V2 (legacy) ยังเป็นแบบเดิม
>
> **แก้เพิ่ม**: `reviewer` ไม่ใช่ "ผู้ดูทั้งหมด" อีกต่อไป (`VIEW_ALL_ROLES` ตัด `reviewer` ออก) — `reviewer` เป็นอาจารย์ธรรมดาทุกอย่าง เห็น/แก้แค่ของตัวเอง ยกเว้นคิวตรวจสอบ (`/verifications/*`) ที่จำกัดเฉพาะอาจารย์ที่หัวหน้าสาขา (`executive`) มอบหมายให้ตรวจ (`reviewer_assignment`, #293) ไม่เห็น report สาขา, ใบภาระงานของคนอื่น หรือผลงานรายปีของคนอื่นเลย

## บทบาทมาจากไหน (#299, #313)

ใช้งานจริงกับ **สาขาเดียว** มีบทบาทหลัก 3 อย่าง: หัวหน้าสาขา (`executive`), เจ้าหน้าที่สาขา (`staff`) และอาจารย์ผู้ตรวจ (`reviewer`) ซึ่งเป็นอาจารย์ด้วยกัน (โครงสร้างข้อมูลยังรองรับหลายสาขาและตำแหน่งระดับคณะ แต่ไม่ได้ใช้)

บทบาทที่ใช้จริงในแต่ละ request คือรวมของ

- Cognito group ใน token (`staff`, `executive`, `admin`; **ไม่นับ `reviewer`**)
- บทบาทที่ admin กำหนดในแอป (`user_role`): `staff`, `admin`
- `executive` ถ้าถือตำแหน่ง `dept_chair` (หัวหน้าสาขา) อยู่ในวันนี้ (`member_position` ที่ยังไม่สิ้นสุด)
- `reviewer` ถ้ามีการมอบหมายผู้ตรวจที่ยังใช้งานอยู่ (`reviewer_assignment` ของรอบที่เปิดและยังไม่ถึง `submit_due_at`)

อ่านทุก request จึงมีผลทันที ไม่ต้อง login ใหม่ เมื่อตำแหน่งหัวหน้าสาขาสิ้นสุด หรือรอบปิด สิทธิ์นั้นก็หายเอง

- admin **มอบ `executive` ในแอปไม่ได้** (ได้จากตำแหน่งหัวหน้าสาขา) และมอบ/ถอน `reviewer` ไม่ได้ (ได้จากการมอบหมาย) แถว `executive` เก่าใน `user_role` ยังนับและ admin ถอนได้
- admin ถอด `admin` ของตัวเอง หรือของ admin คนสุดท้าย ไม่ได้
- Cognito group `reviewer` เดิมไม่นับอีก ส่วน group `executive` เดิมยังนับ จนกว่าจะลบ group ใน AWS

## บทบาท

| บทบาท | ชื่อในแอป | มาจาก | ใคร |
|---|---|---|---|
| `lecturer` | อาจารย์ | ทุกคนที่ login แล้วจับคู่กับแถวใน `lecturer` ได้ | อาจารย์ทุกคน |
| `staff` | เจ้าหน้าที่สาขา | Cognito group `staff` หรือ admin กำหนดในแอป | เจ้าหน้าที่ประจำสาขา: ดู report และรับเรื่องใบภาระงาน (`receiver`) กรอกรายการแทนอาจารย์ได้ (รอเจ้าของยืนยัน) ไม่มีสิทธิ์สร้าง/แก้ master data |
| `reviewer` | อาจารย์ผู้ตรวจ | คำนวณจากการมอบหมายผู้ตรวจที่ยังใช้งานอยู่ (#293, #297) | อาจารย์ด้วยกัน: เป็นอาจารย์ธรรมดา (เห็น/แก้แค่ของตัวเอง) บวกสิทธิ์รับรอง/ตีกลับผลงานตีพิมพ์และหลักฐาน **เฉพาะของอาจารย์ที่หัวหน้าสาขามอบหมายให้ตรวจในรอบนั้น** (เจ้าหน้าที่สาขา หัวหน้าสาขา และ admin ที่ไม่ได้เป็นผู้ตรวจ ดูได้แต่ตรวจไม่ได้) ไม่เห็น report สาขา หรือใบภาระงาน/ผลงานรายปีของคนอื่น |
| `executive` | หัวหน้าสาขา | ถือตำแหน่ง `dept_chair` ในวันนี้ (หรือ Cognito group `executive` เดิม) | หัวหน้าสาขา: ดูได้ทุกอย่าง ทั้ง report ของทุกรอบ และมอบหมายอาจารย์ผู้ตรวจ |
| `admin` | ผู้ดูแลระบบ | Cognito group `admin` หรือ admin กำหนดในแอป | ทำได้ทุกอย่าง (รวมสร้าง/แก้ master data และตำแหน่งบริหาร กำหนดบทบาท) และดู audit log |

ตำแหน่งบริหารใน `member_position` (ไม่ใช่ Cognito group) ใช้กำหนดว่าใคร **ลงนามหรือประเมิน** อะไรได้

- `dept_chair`, `dept_committee` ของสาขา X: ดูใบภาระงานของสาขา X และลงนามขั้นของตัวเอง
- `assessor_position` ของข้อในเกณฑ์ (เช่น `exec_committee`): ให้ค่าข้อนั้นได้

ทุก endpoint ต้อง login ยกเว้น `/health` ถ้าไม่ได้ login ตอบ **401** ถ้า login แล้วแต่ไม่มีสิทธิ์ ตอบ **403**

## ตารางสิทธิ์

"ตัวเอง" = `lecturer_id` ใน path คือคนที่ login "เจ้าของ" = อาจารย์เจ้าของใบภาระงาน
"ผู้ดูทั้งหมด" = `staff`, `executive`, `admin` (ตั้งแต่ #291 follow-up: **ไม่รวม `reviewer`** — reviewer ที่ไม่ได้ assign อะไรเลยเห็นแค่ของตัวเองเหมือนอาจารย์ทั่วไป)

| กลุ่ม endpoint | อ่าน | สร้าง / แก้ / ลบ |
|---|---|---|
| `/me` | ทุกคน | – |
| `/lecturers`, `/lecturers/{id}` | ทุกคน | สร้าง, activate/deactivate: `admin` · แก้: ตัวเอง (ข้อมูลติดต่อ) หรือ `admin` (ทุก field) |
| รูป / CV ของอาจารย์ | ทุกคน | ตัวเอง, `admin` |
| การศึกษา, หัวข้อวิจัยและความเชี่ยวชาญของอาจารย์, โปรไฟล์ภายนอก | ทุกคน | ตัวเอง, `admin` |
| master หัวข้อวิจัย / ความเชี่ยวชาญ | ทุกคน | เพิ่ม: ทุกคน · แก้ / ลบ: `admin` |
| `/publications` | ทุกคน | เพิ่ม: ทุกคน (ต้องใส่ตัวเองเป็นผู้แต่ง ยกเว้น `staff`, `admin`) · แก้ / ลบ: ผู้แต่ง, `staff`, `admin` · ผลงานที่รับรองแล้ว: `staff`, `admin` เท่านั้น (ยังไม่เปลี่ยน — คนละเรื่องกับ master data) |
| การรับรองผลงาน / หลักฐาน | ผู้ดูทั้งหมด (ดูได้แต่รับรองไม่ได้) | `reviewer` **เท่านั้น และเฉพาะของอาจารย์ที่ถูกมอบหมายให้ตรวจ** (ผลงาน: ผู้แต่งคนใดคนหนึ่งเป็นผู้ถูกมอบหมาย, หลักฐาน: ถูกมอบหมายในรอบของใบนั้น, #293, #331) `admin` และ `executive` รับรองไม่ได้ถ้าไม่ได้ถูกมอบหมายเป็นผู้ตรวจ และไม่เห็นคิวตรวจ |
| `/user-roles` (#299, #313) | `admin` | `admin` เท่านั้น (ให้ `staff`, `admin`; ถอนได้รวมแถว `executive` เก่า) |
| `/reviewer-assignments` (V4 #293) | `executive`, `admin` เห็นทุกคู่ · `reviewer` เห็นแค่คู่ที่ตัวเองเป็นผู้ตรวจ · **การมอบหมายผูกกับรอบ (`round_id`) และมีผลเฉพาะตอนรอบ `is_open` และยังไม่ถึง `submit_due_at`** พ้นนั้นจะไม่แสดง และ reviewer จะไม่เห็นคิวตรวจของคู่นั้น | `executive` เท่านั้น (สร้าง/ลบ) สร้างได้เฉพาะรอบที่ยังรับงานอยู่ |
| `/departments`, ตำแหน่งบริหาร, เกณฑ์ (`/rubric-*`), สร้าง/แก้รอบ | ทุกคน | `admin` |
| ใบภาระงานในรอบ, report ของรอบ | เจ้าของ (self) · `dept_chair`/`dept_committee` เฉพาะสาขาตัวเอง · `staff` เฉพาะสาขาตัวเอง (ของอาจารย์ที่เข้าระบบ) · `executive`/`admin` ทุกสาขา · `reviewer` **ไม่มีสิทธิ์พิเศษ** (เห็นแค่ของตัวเองถ้าเป็นเจ้าของ) | – |

| `/submissions`, entries, หลักฐาน | เจ้าของ, `staff`/`executive`/`admin`, `dept_chair` / `dept_committee` ของสาขาของใบ · list ของคนทั่วไปเห็นแค่ใบตัวเอง, `staff` เห็นแค่สาขาตัวเอง · `reviewer` เห็นแค่ใบตัวเอง (ไม่มีสิทธิ์พิเศษจาก role นี้) | เจ้าของ ตอนใบเป็น `draft` / `returned` · `staff` สาขาเดียวกันกรอกแทนได้ แต่รายการจะ "รอยืนยันจากอาจารย์" จนเจ้าของกดยืนยันเอง (#292) |
| ลงนามใบ (`/approvals`) | เหมือนอ่านใบ | ผู้ส่ง: เจ้าของ · รับเรื่อง: `staff`, `admin` · หัวหน้าสาขา / กรรมการสาขา: ผู้ดำรงตำแหน่งนั้นในสาขาของใบ |
| ประเมิน (`/assessments`) | คิวของตัวเอง · ค่าที่ทุกคนให้: เจ้าของ, `staff`/`executive`/`admin` | ผู้ดำรงตำแหน่ง `assessor_position` ของข้อนั้น |
| `/lecturers/{id}/work` (ผลงานรายปี) | ตัวเอง, `staff`/`executive`/`admin`, `dept_chair` / `dept_committee` ของสาขาของอาจารย์ · `reviewer` เห็นแค่ของตัวเอง | – |
| audit log | `admin` | – |

## ตอนพัฒนา (ไม่ใช่ prod)

ถ้า `DEV_AUTH_HEADER_ENABLED=true` และ `ENVIRONMENT` ไม่ใช่ `prod` ใช้ header แทน Cognito ได้

- `X-Lecturer-Id: <uuid>`: ทำในนามอาจารย์คนนี้
- `X-Dev-Roles: staff,admin`: บทบาทเพิ่ม (ไม่ใส่ = `lecturer` อย่างเดียว) ใส่อย่างเดียวโดยไม่มี `X-Lecturer-Id` ได้ ใช้กับ script ที่ยังไม่มีอาจารย์ในระบบ

## ที่อยู่ในโค้ด

- ตารางนี้อยู่ใน `backend/app/v2/permissions.py` (ROUTE_RULES) router ของ `/api/v2` เช็คทุก request จากตารางนี้ เทสต์ fail ถ้ามี route ที่ไม่อยู่ในตาราง
- เรื่องที่ต้องดูข้อมูลก่อนตัดสิน (เจ้าของใบ, สาขาของใบ, ผู้แต่ง) เช็คใน service
